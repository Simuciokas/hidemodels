**Every setting is now a command, and there are far fewer jars to choose between.**

### Settings without opening the config

The three directives that used to be file-only are commands as well:

* `/hidemodels on` / `off` — stop hiding without emptying your list
* `/hidemodels first-person on` / `off` — hide only while the camera is in first person, so the
  model comes back when you press F5
* `/hidemodels radius <blocks>` — the default radius for `list`

Each one edits `config/hidemodels.txt` and reloads it, exactly as `add` and `remove` do. The file
stays the single description of what the mod is doing, so a setting changed in game and a setting
typed into the file can never disagree — and if your file used one of the accepted aliases
(`firstperson`, `disabled`), the command rewrites it in the documented spelling rather than leaving
a second line behind that still counts.

### Click a piece count to open a model up

`/hidemodels list` shows one row per model with its piece count — `x7`. That count is now clickable,
and it lists just that model's seven bones, each clickable in turn.

So hiding a single piece is three clicks: run `list`, click the count, click the bone. Previously it
meant `list bones`, which prints every bone of every model around you — near a couple of mounts that
overruns the forty-row cap before the one you wanted appears. It is typeable too, as
`/hidemodels list bones <radius> <model>`, and the model name tab-completes.

Counts only link where there is something underneath them: in `list bones` the row is already a
single piece, and an id with no bones has nothing to open, so those stay plain text rather than
offering a click that would reprint the line it was on.

### Seven jars instead of twenty-nine

The mod supports the same eighteen Minecraft versions as before, on Fabric, Quilt and NeoForge — but
most of those versions were getting a jar that was byte-for-byte identical to its neighbour's. They
now share one:

| jar | Minecraft |
|---|---|
| Fabric / Quilt | 26.2–26.1 · 1.21.11–1.21.5 · 1.21.4–1.20.5 |
| NeoForge | 26.2–26.1.2 · 1.21.11 · 1.21.10–1.21.5 · 1.21.4–1.20.6 |

Nothing about which versions work has changed; there is simply less to pick from, and each jar
declares the whole range it covers, so your launcher will stop warning you that a jar for 1.21.7 is
being used on 1.21.8.

The versions that genuinely cannot share a jar are the ones where Minecraft itself changed something
the mod touches — the click-event types at 1.21.5, and a class rename at 1.21.11 that affects the
NeoForge build only.

### Tested, as usual, by running it

Every jar in the table above is built and launched on a clean machine before release: the client
starts, loads the mod, and the mod's own checks run against a real world. The client gametest now
also proves that the new clickable count builds a command the game accepts in full, and that the
grouping those links depend on still holds — both are failures that would otherwise turn up as a red
error in your chat rather than in CI.

A separate check compares the jars in each group byte for byte, so the table above can never quietly
become a lie about which versions really do ship the same file.
