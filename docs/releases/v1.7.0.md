**Models built on armor stands are hidden now too — so the mod works with the older plugins, and with the legacy modes of the newer ones.**

### The other way a model gets rendered

Until now the mod only looked at `item_display` entities. That is how ModelEngine, BetterModel,
Nexo and Oraxen's display furniture render today, so most setups were covered — but every one of
those has a legacy mode, and the plugins that came before display entities existed had only one
option: the model piece is an **armor stand wearing the item on its head**.

Same component, same config line, different entity — and the mod silently ignored half of it.

Nothing changes about how you use it. The same `/hidemodels add` line hides either kind, and
`/hidemodels list` reports both. Only the head slot is read: the other slots hold what an armor
stand is actually wearing, and taking those would hide stands for their boots.

**One thing to know:** ordinary armor stands now appear in `/hidemodels list` as `minecraft:diamond_helmet`
and the like, because vanilla items carry a model id of their own. Nothing is hidden that you did
not ask for — the list is just chattier near shops and decorations. Narrow the radius
(`/hidemodels list 16`) if it gets in the way.

### Fabric API now has a minimum version

The jars used to accept any Fabric API at all, including builds from years ago that predate the
client command API this mod registers through — which failed as a crash on a missing class rather
than as "this dependency is not met". Each jar now names the oldest version its own Minecraft range
is actually tested against: `0.155.3` on 26.x, `0.128.2` on 1.21.5–1.21.11, `0.97.8` on
1.20.5–1.21.4.

If you keep Fabric API roughly current, you will not notice. NeoForge is unaffected — it needs no
API mod.

### A better icon

The icon was a crop of a screenshot that cut the lantern and the top of the rider's hat off the top
edge, and sliced the fence off the right. The screenshot was already square, so the crop was never
needed. It is the whole frame now.

### Under the hood

The config poll used to run off the render path, asking the clock whether a second had passed once
per model piece per frame. It runs once per client tick instead. You will not feel the difference —
it was microseconds — but a poll belongs on a timer, and the render path is now four checks ordered
cheapest-first, which is the shape it should have had all along.

### Tested, as usual, by running it

Every jar is built and launched on a clean machine before release: the client starts, loads the mod,
and the mod's own checks run against a real world. The client gametest now also builds an armor
stand equipped the way those plugins equip one and asserts it resolves to its model id and gets
hidden by the config — on both sides of the 1.21.5 change to how entity equipment is stored.

That is a test of the *shape*, not of any plugin: no ModelEngine is installed and none is needed,
because the mod keys on a vanilla component carried by a vanilla entity.
