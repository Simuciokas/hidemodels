**Jars no longer claim Minecraft versions they were not built for.** This is the reason to upgrade,
and it fixes a failure that was invisible when it happened.

Every jar declares which Minecraft it is for, and the 1.21.x jars used to say "this version or any
later 1.21.x" — so Fabric Loader would happily start the 1.21.2 jar on 1.21.11. The mod is remapped
for the version it was built against, and a mixin that no longer matches does not raise an error: it
simply never applies. The result was a mod that loaded cleanly, hid nothing, and left nothing in the
log to explain why.

1.21.x jars now name exactly one Minecraft version, so Loader refuses the wrong one at startup with
a message that says so. There is a jar for every Minecraft release from 1.21.2 onward, so nothing is
left without one. 26.x jars still cover their patch releases — `26.1` also serves 26.1.1 and 26.1.2 —
because those builds are not remapped and really are compatible across them.

**If you are on the matching jar already, nothing about the mod changes.** Same behaviour, same
config file, same command. If you had the wrong jar and wondered why nothing was hidden, this is
why, and the fix is to take the one naming your version.

### Also in this release

* An icon, and links in the mod's own metadata — Mod Menu now shows the mod with a picture of the
  thing it is for, plus source and issue-tracker links.
* Release automation is tidier: the featured version on Modrinth is chosen deliberately rather than
  by whichever upload finished last, and action updates are checked monthly so a deprecated runtime
  or a stale pin shows up as a pull request that has to pass the full test matrix.
